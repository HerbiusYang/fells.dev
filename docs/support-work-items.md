# 客服购买与售后工单

客服工作台的客户详情侧板包含“购买与售后工单”。“业务待办”和“交易待核对”从顶部打开；工单状态独立于聊天状态，关闭聊天不会关闭未完成工单。所有写入通过真实同源服务端接口，绑定客服 Cookie 与预期客服身份；客户只能查看本人工单及确认本人交付。

## 标准成交与交付

1. 选择客户会话，创建报价。包月选择服务端目录返回的套餐和月数，金额和服务天数对应当前真实报价；API 额度输入人民币成交价，服务端冻结所购美元额度。填写负责人、交付期限与约定。
2. 保存“待付款”；财务核验原始充值后，将原收款 ID 关联到工单，保存“待交付”。每笔收款只能关联一个工单，服务端核对客户归属、审批状态、折扣及退款后的实际金额。
3. 在已核验收款的工单下方创建“权益开通”售后事项（activation case），记录原因和核验依据，按需勾选“开启 API Key 自助创建权限”。审核事项中不可更改的客户 ID、原工单 ID、商品金额及账户影响，再点击“执行售后处理”。服务端按原工单冻结的套餐或额度报价实际开通，并保存事项执行回执。报价失效、钱包不足、容量不足或权限不足返回真实错误，保留工单与输入。
4. 客户打开客服窗口，核对开通事项的实际账户变更和服务可用性后点击“确认处理完成”。服务端验证真实账户权益、账本来源及可用性；验证通过才同时完成开通事项与原购买工单。客服不能通过修改状态伪造客户验收。默认界面只有事项开通入口；没有开通事项的历史交付仍兼容原工单“确认可以使用”。

事项创建响应未确认时保留同一创建 UUID 和原始请求。执行重试使用同一事项 ID 作为稳定幂等引用，不重复开通；权限选择与申请金额在创建后冻结，执行成功展示真实账务引用和账户前后对照。备注及变更记录向客户公开，禁止填写账号密码、密钥或内部秘密。

“其他”工单用于人工跟进；自动开通与客户验收只支持可核验交付的订阅和 API 额度工单。API Key 创建权限只能作为这两种真实权益的附带开通。工单变更通过 `order.updated` 事件通知双方，客户端重新读取服务端状态。

## 未决交易恢复

“交易待核对”展示服务端证据、业务引用及处理记录。结果未知或仍在执行时只能记录待核对及责任人，不能重复扣款。服务端确认已提交时可补记回执；服务端确认从未执行时可终结原操作，由客户重新确认下一次业务。两个确认动作均要求填写处理依据并携带当前版本，版本冲突刷新真实状态，同时保留未提交的处理备注。

补记交易回执不代表服务交付验收，工单仍须客户实际确认。队列最多显示 100 条，可用状态、负责人、逾期筛选缩小范围。

## 开通、补偿与退款事项

选中原工单后创建售后事项。每项固定绑定客户 ID 和原工单 ID，保存原因、真实会话消息或已发附件、负责人、处理期限及申请金额/小时。补偿和退款必须关联本会话的真实消息或已发附件，不能仅填写自由文本。创建后金额与类型冻结，执行前明确显示账户影响。

- 开通事项核验原单收款后实际开通权益，可附带 API Key 创建权限。执行后由客户验收；事项验收会同时完成原购买工单，客户页面优先显示事项确认，避免重复验收。没有开通事项的旧交付继续支持原工单确认。
- 补偿仅 Owner 可执行，赠送美元 API 额度或订阅服务小时，不扣人民币现金。权限不足、证据不足或执行失败保持真实未执行状态及草稿。
- 自动退款仅处理未开通权益、未消费的原现金和账务回退，不会自动向外部支付渠道转账。已交付权益退款需人工核对。财务须完成实际原渠道退款，再记录凭证号/说明，并关联真实退款消息或附件。客户确认实际到账才完成事项；已完成退款的凭证字段冻结，后续备注和转派使用稀疏 PATCH。

执行回执展示操作编号、真实账务引用及账户前后对照：人民币现金（余额减赠送余额）、购买及人工赠送美元 API 额度/其中人工赠送份额、该额度期限、API Key 创建权限、计费模式及订阅到期时间。原订单、事项与历史均保留可查。已执行事项进入待核对后，客服须核对原执行回执并填写处理依据，才能恢复为已执行、等待客户验收；恢复只更新状态与历史，不重复发放。未执行事项不能直接改为已执行。

业务待办中的售后事项队列在服务端先筛选待处理、已执行、待核对事项，再取最多 100 条；订单队列同样先筛选未完成订单，较新的已关闭记录不会挤出未决事项。超出 100 条时明确显示截断提示，可按负责人缩小范围或打开客户会话查看原工单事项。客户与客服会话详情分别读取未完成记录和近期历史，再按 ID 去重，优先展示未完成记录；任一列表仍有更早记录时显示查询提示。客户原工单验收的抑制直接查询未完成开通事项，避免旧开通事项被关闭历史遮住而出现双重验收。创建原因最多 1000 字；订阅赠送补偿每项最多 744 小时，API 额度补偿以美元计，金额/小时与原商品类型一致。

订单与售后事项 ID 是服务端 UUID，客户、会话及历史记录 ID 是十进制字符串。创建响应未确认时保留同一 UUID 和原始请求内容；跨会话登录切换会清除旧账户草稿和未决请求，避免继承另一身份的操作。

## 售前登录

购买入口保留商品名称、类型、公开报价及来源路径等公开上下文，存放在当前标签页的 sessionStorage，一小时后过期。账号凭据不进入购买意图。未登录客户会得到含安全 next 参数的登录链接；登录后自动打开客服并预填咨询草稿，由客户确认发送。登录页面切换语言保留合法 next、推荐码、注册入口，不保留任意查询参数。

## 验证

`tests/support-orders.test.mjs` 与 `tests/support-cases.test.mjs` 验证真实 HTTP 契约适配、身份绑定、整数金额、版本、输入上限及失败透传。浏览器套件执行客服报价建单、付款验证失败保留草稿、创建开通事项并重试执行、客户验收、补偿 Owner 校验、退款凭证关联、已执行事项核对恢复、未完成事项队列和截断提示，以及初始化失败重试和登录上下文保留。小屏与六语言布局由客服可访问性套件继续覆盖。
