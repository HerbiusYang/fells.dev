# 客服购买与售后工单

客户从客服窗的“我的订单与历史”查看本人全部订单，按游标加载更早记录。每单可一键发送给客服咨询；消息中的原订单卡片保存服务端标题和成交金额，双方可点击回到原单。客户不能提交其他客户或其他会话的订单。

客服客户详情侧板包含购买订单及其售后事项；顶部业务待办支持按负责人、处理状态、等待方和逾期筛选，并按最早期限优先加载。订单与售后队列都提供游标加载更多。聊天解决状态独立于业务状态。

## 成交和交付

1. 从真实商品目录创建订阅、Token Plan 或 API 额度报价。人民币报价、商品权益及报价依据由服务器冻结；“其他”仅供人工跟进。
2. 核验原收款，关联原收款 ID，并保存待交付。每笔原收款只能关联一张订单。
3. 创建权益开通事项，核对客户、原订单和账户影响后执行。重试同一事项不会重复发放。
4. 客户核对真实可用性后本人确认；有未决开通事项时，原订单不再出现重复验收入口。原单显示交付、售后进度、退款累计与未决事项数量。

旧版已付款 Token Plan 缺少完整权益快照时，Owner 可在原单提出新权益报价，保留原成交金额与收款。客户页面列明保证美元额度、总弹性上限（不是额外增量）、周期及原因，由客户单独确认新报价后才继续开通。报价确认不等于交付验收，也不发确认奖励。

## 14 天无异议结案

客户窗口醒目显示核对政策，每个可核对事项显示服务端准确截止时间。开通和补偿交付后开始 14 天核对期；退款必须在实际打款经独立复核后才开始。第 11 天产生一次持久提醒。截止前无异议时，系统记录“系统结案”，不会写成客户本人确认。

客户可使用“没收到 / 有问题”提交异议，说明会进入历史并暂停自动结案。客服核对处理后恢复待验收，服务器重新确定核对期。前端不依赖本机倒计时推断结案。

客户本人在核对期内确认符合条件的新开通订阅或 Token Plan，可获得随机 0.10–3 美元 API 额度，每账户每个 洛杉矶（America/Los_Angeles）自然月最多 5 美元。续费、单买额度、补偿、退款和系统结案不参与。页面在确认前展示资格、范围、月上限与售后权利，在结果中展示真实到账或月限额未发放。奖励不改变售后权利，也不与人工补偿月上限合并。

## 退款

退款在原单下创建，固定申请金额和证据。已交付权益先提出原权益回收方案，由不同的 Owner 审批后执行。可归属、尚可回收的原单权益按方案回收；Token Plan 比例方案仅支持整期全退停用。原权益已被使用时，可提出“回收原单剩余权益，承担已消费差额”并由不同 Owner 审批，实际回执列明损失。无法回收但保留全部权益的商业让步必须明确申请放弃回收并取得 Owner 审批，不能填写虚构回收结果。

账内处理和支付渠道打款是两步，客户和客服都可看到各自状态。执行不调用外部支付商。财务完成真实原渠道打款后，记录渠道、收款账户、唯一凭证号、精确人民币金额与本会话真实证据。记录只是声明；另一位既非执行人又非录入人的客服复核后，才允许客户确认到账或进入 14 天无异议结案流程。未知或失败打款不允许客户验收。

已核验失败的退款追加冲正，原执行回执不覆盖。事项以 `reversed`（已冲正）终态保留原回执与反向链，不再执行、验收或重开；继续处理须创建关联纠错事项。其他错误权益处理须由 Owner 在原权益仍可追溯回收时冲正。所有回退保存反向账务引用；更正事项通过 `correctsCaseId` 关联同一原单的已冲正事项。退款汇总分开显示已退与待完成金额，部分退款完毕按售后进度表示已结案。

## 补偿

补偿须选择服务中断、交付错误、计费错误或关怀补偿，并关联真实会话证据。只有 Owner 可执行。每客户每个 洛杉矶（America/Los_Angeles）自然月最多 100 美元 API 额度、744 服务小时、1 个原 Token Plan 周期，服务器事务内核验累计。客服可查看月度客户补偿报表。补偿和售后核对不抹掉原购买交付事实。

## 并发和恢复

所有写入绑定真实 Cookie、audience 和预期身份。创建结果不明时保留同一 UUID、原载荷和草稿。修改、审批、渠道记录、复核、异议和冲正携带打开时的版本；冲突后核对最新记录再提交，不能把旧草稿自动套到新版本。身份切换会关闭旧连接、清空该身份草稿和未决请求。

真实 `order.updated` / `case.updated` SSE 驱动双方重读状态，15 秒轮询补充刷新。金额、执行回执、渠道成功、系统结案与奖励均以真实服务端响应为准。

客户订单列表保留后端 `historySyncPending` 元数据；旧购买记录尚在同步时显示提示，继续提供已同步记录与游标加载。14 天政策区明确结案后仍可反馈。
